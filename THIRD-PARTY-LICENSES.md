# Third-party licences

Pulse redistributes open-source code. This file is the attribution notice for it.

**It is generated, not written.** `scripts/gen-third-party-licenses.sh` reads the licence
text out of the Go module cache and `web/node_modules` and emits this file, so an entry can
never claim a licence its dependency does not carry. Regenerate it whenever dependencies
change; `--check` mode fails if it is stale.

## What is in scope, and what is deliberately not

Listed here is the code that ends up **inside a shipped artifact**: the Go modules linked
into the `pulse` binary, and the npm packages bundled into the built web UI.

**Build- and test-only dependencies are excluded on purpose.** Vite, ESLint, TypeScript,
Vitest, Playwright, the Go toolchain and the builder images never reach the artifact, so no
distribution obligation attaches to them. If you grep this file for `vite` and find nothing,
that is the reason, not an omission.

**Third-party container images are also excluded from the attribution tables below**, for a
different reason: Pulse *pins image references*, it does not rebundle images. Your Docker or
Kubernetes pulls ClickHouse, Caddy, Postgres and busybox from their own upstream registries,
so Pulse is not their distributor. They are named in the last section for completeness.

| `sdk/beacon-swift` (`PulseBeacon`) | MIT |

Both SDKs ship with **zero runtime dependencies**, so embedding either one adds no
third-party obligations of its own. That is a verified property, not an aspiration:
`sdk/beacon-js/package.json` declares no `dependencies` (only build tooling under
`devDependencies`) and its published bundle is self-contained; `sdk/beacon-swift/Package.swift`
and `ios/PulseKit/Package.swift` both declare no package dependencies.
