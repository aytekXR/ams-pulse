Privacy Policy

Last updated: 2026-07-28

Pulse is self-hosted software for monitoring Ant Media Server deployments. This privacy policy explains what data Pulse collects, how it is stored, and who controls it.

1. Self-hosted architecture

Pulse runs entirely on infrastructure you operate. The software does not send data to Anthropic, Beyond Kaira, or any third party by design. All monitoring data stays on your servers.

You are the data controller. If you operate a Pulse deployment, you decide what data is collected, how long it is retained, and who has access. This policy describes the software's default behavior; your deployment may differ.

2. Data collected by the Pulse server

The Pulse server collects two categories of data from your Ant Media Server:

2.1 Stream and node metrics (via AMS REST API)

Pulse polls your Ant Media Server's REST API to collect operational metrics:

  • Stream identifiers, bitrate, viewer counts, protocol type
  • Node CPU, memory, and disk usage (cluster deployments)
  • Application names and stream names
  • VoD recording metadata (file size, duration)

This data describes your streaming infrastructure. It does not include video content or personally identifying information about viewers.

2.2 Viewer quality-of-experience (via beacon SDK, optional)

If you embed the Pulse beacon SDK in your video player, the SDK sends playback events to your Pulse server. These events include:

  • Session identifier (random UUID, not linked to user identity)
  • Stream identifier and application name
  • Playback events: startup time, rebuffering, bitrate changes, errors
  • Watch duration and heartbeat timestamps
  • Player type and SDK version

The beacon SDK does not collect:

  • Device identifiers, advertising IDs, or persistent tracking IDs
  • Names, email addresses, or other personal contact information
  • Precise geolocation (GPS coordinates)
  • Browsing history or third-party cookies

IP address and user agent: When the beacon sends events, the Pulse server extracts the viewer's IP address (from the HTTP request) and User-Agent header. If you configure a GeoIP database (PULSE_GEO_MMDB_PATH), the server resolves the IP to a country and region for geographic analytics. The raw IP address is not stored in the default schema.

2.3 Retention

Data retention is configured by the operator. ClickHouse TTL policies control how long metric rows are kept. The default configuration retains raw events for 90 days and aggregated rollups longer. You can adjust these settings in your deployment's ClickHouse schema.

3. The Pulse iOS app

The Pulse iOS app is a monitoring client that connects to your Pulse server. The app itself does not collect or transmit data to any third party.

3.1 What the app stores locally

  • Server URL: The URL of your Pulse server, stored in the iOS Keychain (encrypted at rest).
  • API token: Your bearer token for authenticating with the Pulse API, stored in the iOS Keychain.

The Keychain is the iOS-recommended location for credentials. Data stored there is encrypted and excluded from unencrypted backups.

3.2 What the app transmits

The app communicates only with the Pulse server URL you configure. All requests use HTTPS. The app does not contact any other server. There are no analytics SDKs, advertising networks, or crash-reporting services embedded in the app.

3.3 What the app does not collect

The Pulse iOS app does not collect:

  • Device identifiers (IDFA, IDFV)
  • Location data
  • Contacts, photos, or other personal data
  • Usage analytics or crash reports sent to the developer

4. This website

This website (the pages you are reading now) is static HTML. It does not:

  • Set cookies
  • Use JavaScript analytics (no Google Analytics, Plausible, or similar)
  • Load resources from third-party domains (no CDN fonts, no external scripts)
  • Collect form submissions (there are no forms)

The web server may log standard HTTP access logs (IP address, timestamp, requested URL, user agent) for operational purposes. These logs are controlled by whoever hosts the website.

5. TestFlight beta (Apple)

If you install the Pulse iOS app via TestFlight, Apple collects certain data as part of its beta testing program. This collection is governed by Apple's privacy policy, not ours.

According to Apple's TestFlight documentation:

  • Apple collects crash logs and app usage data from beta testers.
  • Developers (us) can see crash reports and aggregate usage statistics but cannot identify individual testers by name.
  • Testers can opt out of sharing crash data with developers in iOS Settings.

For details, see Apple's Privacy Policy and TestFlight documentation.

6. Third-party services

The Pulse software itself does not integrate with third-party services. However:

  • Your Pulse deployment may connect to external services you configure (e.g., Kafka brokers, SMTP servers for alerts, OIDC providers for authentication). Data shared with those services is governed by their respective privacy policies.
  • GeoIP enrichment requires a MaxMind GeoLite2 database file that you obtain separately. MaxMind's data license terms apply to your use of that database.

7. Your rights

Because Pulse is self-hosted, data subject requests (access, deletion, correction) are handled by whoever operates the Pulse deployment. If you are a viewer whose data was collected by a Pulse deployment, contact the organization that operates that deployment.

If you operate a Pulse deployment and need to respond to data subject requests, you can query and delete data directly in ClickHouse.

8. Changes to this policy

This policy may be updated as the software evolves. The "Last updated" date at the top reflects the most recent revision.
